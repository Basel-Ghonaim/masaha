# 214. The Home test's wait finds Home's own search box

**Status:** Resolved · **Date:** 2026-11-08 · **Resolved:** 2026-11-08

**Evidence:** `apps/web/src/pages/site/public/home/HomePage.component.test.tsx` › «Set my location on the map» failed twice in CI on #137, which changed no app code (run 42384998638, attempts 1 and 2), and passed locally alone. Both attempts failed in 156 ms and 206 ms, far under the lane's 3 s wait, at the line that expects the search box to be in the document, with "element could not be found in the document": `findByRole` had returned an element, which was then removed from the page. The test waited for the router's location to read `/spaces?view=map`, then for a search box named "Search for a space". The location changes before React draws the Directory in Home's place, and Home's hero search (`HomeSearch.tsx`) has the same accessible name as the Directory's. On a loaded runner the wait found Home's box in that gap, and React then removed Home with it. No lazy load was involved: the search sits outside the map's `Suspense`, and the file had already imported the pages before its tests (findings [28](28-the-tests-that-wait-for-a-lazy-page-can-time-out-under-load.md), [55](55-a-files-first-wait-for-a-lazy-shell-outlasts-three-seconds-on-a-busy-machine.md) and [87](87-the-owners-shell-cold-loads-the-space-links-index.md) are another cause).

**Resolves when:** the test waits for content only the Directory draws before it reads the search box, and its full lane passes repeatedly.

**Resolution (#139):** after the location, the test waits for the Directory's own heading, «Workspaces» (Home has none of that name), then expects exactly one search box of that name, which `getByRole` refuses if there are two. The file's first load also moves to `warm(...)` with a 60 s timeout ([testing §3](../../development/testing.md#3-rules-that-bind-every-test), rule 8), which the file did not yet follow. No wait or timeout is raised, and no app code changes.
